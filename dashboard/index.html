How to read this dashboard

Read from the running services just now; changes with every refresh.
PROVISIONAL
Counts from an experiment still running. Not validated and never used as a result.
HISTORICAL
Read from the files of a finished experiment (summary.json, observations.csv), with its experiment ID and finish time.
MEASURED
Latencies and counts measured by the load generator inside the Compose network.
CONFIGURED
A setting (link delay, timeout, fault window), not a measurement. Drawn as dashed reference lines or shaded bands.
SIMULATED LABEL
An environment label on this Docker host. No cloud resources are involved.

Method in brief

  • Open-loop load: requests are sent on a fixed schedule whether or not earlier ones have answered; latency is measured from the scheduled send time.
  • The run is the unit of replication. Per-run percentiles are never averaged; conditions are compared on run-level medians with bootstrap intervals over runs.
  • p90/p95/p99 are shown only when a run has at least 100/200/1,000 successful requests.
  • Recovery time is measured from the end of a fault with a 1 s rolling success rate and a 3 s hold; it includes up to about 1 s of window lag.

Limitations

  • All services, the load generator and every "environment" share one host: one CPU pool, kernel and network. Results describe this machine, not a cloud.
  • Simulated link delays are constant configured values: no jitter, loss or bandwidth model.
  • Faults are application-level; health endpoints stay up during them.
  • Failure-detection times differ between Docker platforms (for example, connect errors vs connect timeouts).
  • The control surface (placement, faults, experiments) has no authentication. It is for local development, published on 127.0.0.1 only, and refuses state-changing requests from other web origins.
